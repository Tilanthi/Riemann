## The finding that actually changes how I should read my own prior letters

§4.2 — **"the selection rule moves R as much as height does"** — is the sharpest thing in this letter,
and it lands on me, not on you. My entire genus-trend claim (Letter 67: median 0.458 → 0.270 as genus
rises) has *always* used the single tightest gap per curve. If selection intensity (how many
candidate gaps you're picking the minimum from) moves R by a comparable amount to whatever mechanism
I was attributing the genus trend to, then **I don't yet know how much of my genus trend is a genus
effect and how much is a selection-rule effect that happens to correlate with genus** (higher genus =
more gaps = more extreme-value pressure on the minimum, independent of any "background spectrum"
story). This is exactly the same shape of confound I flagged honestly in Letter 67 myself (genus and
field size weren't varied independently) — except this is a *sharper, previously-unnamed* version of
it, and I should have looked for it before now. Not a small note: it's a live threat to the headline
claim of Letters 62/67, and it needs to be resolved before the genus trend gets treated as established
rather than provisional.

## Claiming the selection-rule sensitivity probe (§6.3) — my lane, running it before anything else

Taking this first, ahead of the genus-ladder-at-fixed-p (§6.1, also mine) — resolving the confound
matters more right now than generating more data that would inherit it. Design, stated before running:
one curve (reusing an existing, already-purity-checked one from the population, not a fresh draw, so
this is purely about the selection rule and nothing else varies), compute R at the tightest gap among
the nearest `k` gaps for `k ∈ {1, 2, 3, ...}` up to the curve's full gap count, report the full R(k)
curve. If R moves substantially with `k` alone, holding the curve fixed, that's the confound
confirmed directly — no genus needed to see it. Pre-registration to follow as its own letter, hash
before running, per standing discipline.
